Stable technical evidence from the protocols

Days 1–10 followed when each wall fell. With the repository public, this note freezes what we treat as wire-stable: named endpoints, lengths, KDF labels, record prefixes, and ordering constraints that captures and live restores keep forcing into the code. Narrative dates stay in those earlier posts; here the spine is stated as evidence.

Apple can still change private surfaces. Constants below are what IKE encodes today after repeated verification—not a contractual API. Where a value is account- or capture-specific, it is marked as such.

End-to-end spine

  1. GSA (GsService2 + Anisette CPD) → setup.icloud.com session / PET.
  2. Container com.apple.backup.ios / bundle com.apple.backupd; zones _defaultZone, mbksync.
  3. Bootstrap: zones → BackupAccount → D:<sha> → S: → (optional mobilebackup stub) → {deviceSha}:Lock → post-Lock N: / EN retrieves.
  4. Escrow / PCS KeySet (zone masters) before Lock and before any authorizeGet; decrypt backupProperties when the KeySet is present.
  5. Per-domain fileList → authorizeGet (application/vnd.com.apple.me.ubchunk+protobuf) → FileGroups → edge GET with content-byte-range (Ford CT vs data ChunkInfo).
  6. contents.protectionInfo → IKM → HKDF-SHA256 salt PCSMMCS2 → Ford open → checksum21 chunk map → plaintext.
  7. Disk: Backup/xx/<fileID>, Manifest.db, iTunes sidecars.
  8. ADP Octagon: iCDP bottle + device passcode or Recovery Key → fetchRecoverableTLKShares → OpenVault.

GSA, Anisette, and CPD

Commercial suites hit ADP as a hard wall (EPB still returned 403 with ADP on). The research path uses native GrandSlam, not only idmsa web tokens.

  • Lookup then init against https://gsa.apple.com/grandslam/GsService2/. Init carries A2k, Apple ID u, cpd, and ps ["s2k", "s2k_fo"]. Complete carries only u, c, M1, cpd—an extraneous M2 field produces ec=-22410.
  • Default SRP iteration count when the server omits i: 20016.
  • CPD is built from Anisette headers (GrandSlamCpdBuilder): at minimum X-Apple-I-Client-Time, timezone/locale, X-Apple-I-MD, X-Apple-I-MD-M, X-Apple-I-MD-RINFO, X-Apple-I-MD-LU, X-Mme-Device-Id, plus bootstrap / svct=iCloud flags. AuthKitWin vs akd profiles differ in capp and related fields.
  • Stable RINFO constants in code: Windows 84215040; iOS/akd 17106176. Soft reuse of machine data is capped (~3 minutes Client-Time refresh without reminting MD); reminting mid-SRP breaks init/complete pairing (-22410 again).
  • After GSA: setup.icloud.com configurations/init and authenticate. Trusted-device secondary auth needs a PET (com.apple.gs.idms.pet) for later escrow Basic auth.

CloudKit backup surface

  • Binding: container com.apple.backup.ios, bundle com.apple.backupd; zones _defaultZone and mbksync.
  • Record prefixes used end-to-end: D:<sha> (device), S: (snapshots), N: (post-Lock file-list / EN retrieves), KA: / MA: / LA: / NA: / JA: (asset families), :CN: / CN: (modern checksum entries), K: (keybag). Fixed name BackupAccount (no prefix).
  • List path: zones → BackupAccount → D: → S:. Restore bootstrap comment in code: zones → Account → D: → S: → (mbs) → Lock → N:. Zone retrieve prefers record/retrieve, falls back to zone/retrieve.
  • Optional Mobile Backup stub hosts (p32-mobilebackup.icloud.com / {partition}-mobilebackup.icloud.com), Accept application/vnd.com.apple.mbs+protobuf, header X-Apple-MBS-Protocol-Version: 2.2. Stub vs full heuristics live in the download service (small stub threshold vs multi-kilobyte manifest).
  • Zone-master cache artifacts: mbksync_zones_retrieve.bin, directory mbksync_zone_masters. Escrow → PCS KeySet must land before Lock and before any authorizeGet.

Lock (Prepare Restore Session)

The diary name “Prepare Restore Session” is the ordered bootstrap plus CloudKit Lock. IKE’s entrypoints are PrepareDownloadAsync / AcquireRestoreLockAsync—there is no separate public RPC symbol named PrepareRestore in this tree.

  • Lock record: name {deviceSha}:Lock (no leading hyphen on the sha), type Lock, zone mbksync, owner field = device SHA (strip D:). Duration encoded as 172800 seconds (48 h). Operation family: private modify-records (inner type 210 in our builder).
  • Rejection signature: response contains Invalid lock id (attributed to MobileBackupServerExtension). Historical protobuf double-wrapping of named fields produced wrong Lock shapes (Lockb9 vs Lockb7) with the same error.
  • Foreground Restore metadata rides in auth tokens (CAog… family). Analyzed captures for one account showed stable HardwareId / plist SHA across many sessions; that pair is not claimed universal. mme-client-info varies and is merged from live responses. Default prototype string in tooling references an iPhone OS / CloudKit client info template.
  • Post-Lock: large record/retrieve waves feed PreAuth / N: / EN material used by MMCS.

backupProperties

  • CloudKit field name backupProperties (encrypted bytes on the snapshot). Ciphertext shorter than ~16 bytes is not treated as live encrypted payload.
  • Decrypt path: ShareProtection (zone and/or one-shot snapshot catalog unwrap) → CUWK with label backupProperties → PCSFP-GCM with AAD type0 = field name. Zone-only DecryptKey is insufficient; PCS KeySet absence leaves the field marked encrypted.
  • Plaintext Lockdown.* fields (UDID, model, serial, …) feed UI and prefer writing into Info.plist / Manifest.plist when available.

MMCS authorizeGet, FileGroups, edge GET

  • URL shape: {contentHost}/{dsid}/authorizeGet. Hosts come from {partition}-content.icloud.com or per-record ContentBaseUrl.
  • Request/response media type: application/vnd.com.apple.me.ubchunk+protobuf. Request header x-apple-mmcs-auth.
  • Auth header format: {hex21_f2} {hex21_f17} {CAog…}—21-byte tokens (lead 01 or 04 + 20-byte digest). PreAuth wire scan pattern: 12 15 01… (f2) → 2a … CAog (f5) → 8a 01 15 01… (f17). Decoded CAog is expected to contain Foreground Restore and leading signed-FG markers.
  • Per-file authorizeGet entry: f1 = Assets.assetSignature verbatim (21 B, typically 0x04‖20B); f2 = CAog token string; f4 companion typically 0x01‖20B. Never substitute the CK mmcs-auth part0 as f1. Batch header rebuild uses entry[0]: hex(f1) + hex(f4) + ascii(f2).
  • Response: structured FileGroups—one group maps to one edge GET host (URL assembled from template fields). Nested ChunkInfo on the group: checksum (21 or 45 B), chunkEncryptionKey, ctLen, packOffset. Trailing file-checksum chunk references drive assembly order. Incomplete plans (missing URLs/signatures, range sum < declared size) are hard failures.
  • Edge GET query includes content-byte-range={start}-{end}. The same host object can expose Ford ciphertext at offset 0 and data ChunkInfo bodies at other ranges.
  • Asset name patterns include MA:udid:uuid:checksumB64:size and :CN:uuid:checksumB64.

IKM and Ford key material

  • IKM comes only from owned-record contents.protectionInfo unwrap with the zone master (16 or 32 B unwrapped key). The file-list EncryptionKey is the wrong key for Ford and poisons opens.
  • Ford KDF (capture-validated): HKDF-SHA256(ikm=fileKey, salt="PCSMMCS2", info="", len=64)—not the swapped salt/info orientation. Output length 0x40.
  • Ford blob layout: lead(1) ‖ nonce(16) ‖ body, with body = tag(16) ‖ ciphertext from offset 0x11. AES-SIV (RFC 5297) associated data = [nonce, lead]. Per-chunk key expansion uses HKDF info signature-key (0x60 bytes → k1/k2/k3).
  • Classic Auth Ford CT lengths: ctLen ∈ [0x12, 65536]. Larger multi-key bags (ctLen > 64 KiB, sanity cap 32 MiB) require a ByteRange whose length is at least ctLen. Empty-host Ford scan windows include fixed lengths (112…480) with a small scan cap (~4 KiB).
  • Ford gate descriptors often carry a 45-byte checksum with lead bytes 0C 0F 01 04, distinct from 21-byte data checksums.

ChunkInfo, checksum21 cache, LiveFill order

  • Data ChunkInfo binds offset/length to a 21-byte checksum (MAC material uses the trailing 20 bytes). Staging header length 0x28; a little-endian u64 at hdr[0x20] is the data buffer length on the wire.
  • On-disk / session cache under .chunks/ (or tmp CChunkCache), filenames = lowercase hex of the signature (42 hex chars for 21 B, 90 for 45 B gates). Ford gate plants require size == ctLen and typically lead 0x04 before commit; data CI21 may exceed 64 KiB.
  • LiveFill order that survived: authorizeGet → FileGroups → ranged host GET → Ford SpillOpen (exact ctLen, lead 0x04, BlobOpensExactWithIkm; never plant Ford without IKM) → FillChunks for storages that already have Ford keys → data ChunkDecrypt. Map keyed by Auth checksum21 accepts any data lead; Ford-prefix poison detection blocks data slices that open as Ford.
  • Per–file-list / per-domain MmcsChunkAssemblySession shards keep FileGroup caches from cross-contaminating parallel domains.

Lead 0x04 vs 0xC4

  • Typical Ford ciphertext at host offset 0 starts with 0x04. Strict gate-cache readers require compact[0] == 0x04.
  • Valid data chunks may start with 0xC4 and other non-0x04 leads (observed live lengths well above 64 KiB). Requiring 0x04 on data was a classifier bug; the fix is plant-under-hex(checksum21) regardless of lead.
  • Gate45 prefix 0C0F0104 is metadata inside the 45-byte Ford descriptor—not the data lead byte. Orphaned CloudKit names and third-party on-device crypto sit outside this path.

iTunes-shaped output

  • Device tree: {root}/{udid}/[{snapshotGuid}][{timestamp}]/ with clean Backup/ and work tmp/ (flist DBs, AUTH, keybag, mmcs cache, .chunks—removed after success).
  • Asset path: Backup/{fileID[0..2]}/{fileID} where fileID is SHA1 hex (IKE uses SHA1(domain + "-" + relativePath) for Manifest rows).
  • Manifest.db from decrypted MA: candidates (SQLite magic after decrypt; encrypted aliases may be retained). Sidecars: Info.plist (XML), Status.plist, Manifest.plist (bplist)—Manifest.plist prefers a copy of decrypted backupProperties.
  • Catalog evolution in tooling: modern S: → :CN: → EN:; classic S: → M: → files.

Octagon: iCDP bottles and device passcode

  • Escrowproxy get_records lists bottles; Octagon-relevant labels com.apple.icdp.record.*. Recover against HSM is scarce (~10 attempts per record in lab notes)—tooling treats recover as irreversible.
  • SRP secret is the device passcode, not the legacy PCS dsid:dsid path. Identity uses dsid with x = H(salt ‖ H(dsid ":" passcode)) (padded session key variants exist in the escrow client). HTTP Basic(email, PET). Wrong M1 surfaces as credential errors (e.g. -6015); wrong recover header version can yield CLUBH -6122.
  • EscrowBottle plaintext exposes BottledPeerEntropy (~72 B). Cuttlefish container com.apple.security.keychain / cuttlefish coderouter: fetchViableBottles → AES-GCM OTBottle Contents → peer signing/encryption keys → KeySet for the circle / backup PCS path.

Octagon: Recovery Key and TLKShares

  • Local KDF (RK is not “sent as a password”): HKDF-SHA384(ikm=UTF-8(RK), salt=UTF-8(altDSID), info, 56) with info Recovery Signing Private Key / Recovery Encryption Private Key. Deterministic P-384 keygen (k = (entropy_be mod (q-1)) + 1). PeerId = RK- + Base64(SHA384(signing public key data)).
  • Cuttlefish fetchRecoverableTLKShares for that peer (protobuf string field 1 then 2). Prod path avoids a legacy RPC spelling that returned HTTP 500. Parses tlkshare / synckey records (names in the tlkshare-…::RK-… family).
  • Unwrap: ECIES blob from wrappedkey with the derived encryption private key → per-view TLKs. Wrong RK: shares may list but unwrap count is zero. OpenVault default views: Manatee, ProtectedCloudStorage, Passwords—feeding PCS seed for ADP zones and backupProperties.

What we do not claim

  • Private CloudKit / MMCS / Cuttlefish stability as a contract—experimental MIT software can break when Apple moves.
  • Completeness = every historical filename (orphans, third-party encryption).
  • Universal Foreground HardwareId / plist SHA (stable across many captures for one analyzed account; others may differ).
  • Forever-green emulated anisette; reproducible GSA needs a coherent ADI/akd-class stack (local Frida or a maintained remote Anisette server).

The public experimental note still applies: signed builds, Forensis-Lab attribution, no warranty that tomorrow’s wire matches today’s evidence table.
